## 검증 방법

`npm run check`가 브라우저 없이 세 가지를 돌립니다.

1. `npx tsc --noEmit` 타입 검사
2. `scripts/smoke.ts` 로직 점검: 14분 자동 플레이, 적 14종 단독 동작, 스킬 14종 발동, 방패적 처치 가능 여부, 레벨업 스탯 2개 추첨, 난이도 강화 반영, 사망 원인 기록, 적 200마리 성능, **하드 상점(17번)**
3. `scripts/boot.ts` 부팅 점검: 최소 DOM을 흉내 내어 메인 화면 → 상점 → 게임 시작 → 일시정지 → 레벨업 → 게임오버까지 키 입력으로 밟습니다

`npm run survival`은 회피에만 집중하는 봇으로 생존 시간을 잽니다 (`npm run survival -- 25 5` = 최대 25분, 시드 5개). 밸런스를 만진 뒤 생존 시간이 어떻게 움직였는지 보는 용도입니다. **봇은 사람보다 약하므로 절대 기준이 아니라 변화량을 보는 지표로만 쓰십시오.** 이 값으로 "깰 수 있다 / 없다"를 결론짓지 마십시오 (2026-09-06 사용자 지시). 격차가 얼마인지 정확히 모르고, 특히 봇은 대시를 위기에 아껴 쓰지 못해서 **장치가 많이 켜진 후반일수록 실제보다 더 나쁘게 나옵니다.** **시드마다 편차가 매우 크므로 3개로는 판단하지 마십시오.** 6개는 써야 중앙값이 흔들리지 않습니다.

`npm run levelcurve`는 **죽지 않는 봇**으로 30분을 완주시켜 "몇 분에 몇 레벨인가"와 "판당 스킬 선택이 몇 번 오는가"를 잽니다 (`npm run levelcurve -- 30 3 0` = 30분, 시드 3개, 난이도 0). 생존 시간을 재는 것이 아니라 경험치가 쌓이는 속도를 보는 것이 목적이라, 생존 실력이 결과에 섞이지 않도록 매 프레임 체력을 되돌립니다. **`SKILL_MAX_LEVEL` 이나 `LEVEL.skillLevels` 를 만지면 반드시 이걸 돌리십시오.** 상한만 올리고 선택 횟수를 안 늘리면 위쪽 레벨이 존재하지 않는 것과 같아지는데, 그 사실이 이 출력에만 드러납니다.

### 봇을 고친 것 (2026-08-12)

**봇이 사람보다 2~3배 약하게 나오고 있었고, 그 탓에 잘못된 결론을 냈습니다.** "난이도 8은 30분 클리어가 불가능해서 해금 사슬이 끊긴다"고 판단했는데, 봇을 고치니 중앙 21분 · 최대 25분이었습니다. 네 가지 중 셋을 고쳤습니다.

1. **빌드를 못 몰았습니다 (제일 큼).** `choices[0]` 을 그냥 집었는데 선택지는 위치를 못 읽게 섞여 나오므로 **사실상 무작위 빌드**였습니다. 판당 19번을 네 스킬에 고르게 흩뿌려 전부 4~5레벨에 머뭅니다. 사람은 두 개에 몰아 만렙을 만듭니다. **스킬 상한을 7 로 올린 이번 조정의 이득이 통째로 "몰아 키우기"에 있는데 봇만 그걸 못 했습니다.** `pickChoice` 로 고쳤습니다 (빈 칸부터 채우고, 다 차면 이미 가장 높은 것을 올림)
2. **예고를 아예 안 봤습니다.** `w.telegraphs` 와 `w.pendingBlasts` 가 위험 계산에 없어서 돌진 통로·시체 폭발·폭격기 예고 한가운데 서 있었습니다
3. **장판은 들어간 뒤에야 반응했습니다.** `d < 0` 일 때만 셌습니다. 지금은 가장자리부터 꺼립니다
4. **대시를 쿨마다 흘려보냅니다 (안 고쳤습니다).** 무적을 위기에 아껴 쓰는 것이 대시의 전부인데 봇은 쿨이 돌면 그냥 씁니다. 흉내 내려면 봇을 크게 고쳐야 하고, 그러다 보면 봇을 만드는 일이 게임을 만드는 일을 밀어냅니다. **봇이 사람보다 약한 이유가 아직 여기 남아 있다는 것만 기억하십시오**

고친 뒤 값입니다 (6시드, 최대 30분). 괄호 안이 **후반 곡선을 편 뒤**(열 번째 조정) 다시 잰 값입니다.

| 난이도 | 상점 없음 | 절반 구매 | 전부 구매 |
|---|---|---|---|
| 0 | 7분 34초 (8분 02초) | (29분 59초 · 3/6 완주) | 29분 59초 5/6 (**6/6 완주**) |
| 8 | 0분 24초 (0분 24초) | 7분 48초 (8분 15초) | 21분 16초 (**25분 26초 · 1/6 완주**) |
| 9 | 0분 11초 (0분 11초) | 5분 05초 (4분 00초) | 9분 58초 (**11분 10초**) |

**곡선을 펴면서 후반이 전체적으로 10~20% 쉬워졌습니다.** 30분 적 체력이 x10 → x7 이 됐으니 당연한 결과이고, 이건 곡선을 펴는 것과 맞바꾼 것입니다. 같은 난도를 유지하면서 직선으로 만들려면 `hpPerMinute` 를 0.2 → **0.3** 으로 올려야 하는데(30분 x10), 그러면 **15분 시점이 x5.5 로 예전 x4 보다 매워집니다.** 직선은 끝점을 맞추면 초반이 세지고, 초반을 맞추면 끝점이 약해집니다. 둘 다 가질 수는 없습니다.

"절반 구매"는 영구 강화 각 항목 10단계 · 가중치 상한의 절반 · 부활 1회 · 시작 스킬 1개입니다 (`saveFor`).

**티어가 넷이 됐습니다** (2026-09-06). `하드 상점까지` 는 스탯 25단계 · 경험치 · 시작 스킬 숙련 · 무장 확장을 전부 산 상태입니다. **다만 `hardMode` 는 안 켭니다.** 지금 하드에는 난이도 규칙이 없어서 켜면 시작 장착만 줄어든 채 적은 그대로인 판이 되고, 그건 하드를 잰 것이 아니라 "장착 칸만 다른 일반 판"을 잰 것입니다. **하드 표가 붙으면 그때 켜십시오.**

**`saveFor` 가 단계 상한으로 `costs.length` 를 쓰면 안 됩니다.** 비용표가 하드 구간까지 25개를 들고 있어서, 그대로 쓰면 "절반 구매"가 10단계에서 13단계로 조용히 올라 예전 측정값과 견줄 수 없게 됩니다. 지금은 `PERM_MAX_LEVEL` 을 봅니다.

여기서 새로 읽히는 것 셋입니다.

- **상점 없이 난이도 8·9 는 20초 즉사입니다.** Lv.2 에서 죽어 스킬을 한 장도 못 고릅니다. 다만 정상 경로에서는 안 생깁니다 (8을 열려면 7을 깨야 하고 그때면 상점이 차 있습니다). `?unlock` 으로 건너뛴 경우에만 만나는 상황이라 급하지 않습니다
- **난이도 8 이상은 빌드가 운에 크게 좌우됩니다.** 난이도 8부터 선택지가 3장 → 2장(`skillChoiceAdd: -1`)인데, 난이도 9 절반 구매의 시드별 편차가 **1분 52초 ~ 21분 33초로 11배**입니다. 키우려는 스킬의 업그레이드 카드가 2장 안에 안 뜨면 못 올립니다. **선택 횟수를 19회로 늘려놓고 장수를 줄인 것이라, 이 항목은 이번 조정과 정면으로 부딪힙니다**
- **코인이 폭증했습니다.** 난이도 8 전부 구매가 판당 **2,861 코인**입니다 (옛 봇으로는 454). 영구 강화 전부(172,295 코인)가 60판이면 끝납니다

레벨업에 스탯이 2개씩 오르면서 상점을 산 판이 5분 45초에서 7분 34초로 늘었습니다. 첫 판은 레벨이 낮아 거의 그대로입니다. 성장의 이득이 후반에 몰린다는 뜻이라, 초반이 너무 맵다고 느껴지면 이 지점부터 보십시오.

자폭적 재설계 뒤 상점 판이 다시 7분 34초에서 8분 28초로 늘었습니다. 그때 봇은 시체 폭발 예고를 못 피했는데(지금은 봅니다) 그런데도 생존이 늘었다는 것은, "맞으면 무조건 점화"가 사라진 이득이 시체 폭발의 손해보다 컸다는 뜻입니다. 자폭적이 너무 순해졌다고 느껴지면 `triggerRange` 나 `fuse` 부터 줄이십시오.

초반이 과하다고 느껴지면 `SPAWN.rateStart`(1.3)를 먼저 낮추고, 그래도 매우면 겁쟁이 해금 조건 `ENEMY_TABLE.coward.unlockSkills`(1 → 2)을 늦추십시오. 이 둘이 초반 난도를 좌우합니다.

재미는 이걸로 검증되지 않습니다. 반드시 직접 플레이해서 확인하십시오.

### 스무 번째 조정 (2026-09-06, 하드모드 상점)

#### 측정 도구도 같이 고쳤습니다

**`saveFor` 가 `costs.length` 를 쓰고 있었습니다.** 그 값이 20에서 25로 늘면서 봇의 "절반 구매"가
10단계에서 **13단계로 조용히 올라갈 뻔했습니다.** 예전 측정값과 견줄 수 없게 되므로
`PERM_MAX_LEVEL` 을 기준으로 바꿨습니다. **비용표의 길이를 상한으로 삼는 코드가 더 있는지
살펴보십시오.**

**봇에 `hard` 티어가 생겼습니다** (`npm run levelcurve`, `npm run survival`). 다만 이 티어는
**`hardMode` 를 켜지 않습니다.** 지금 하드에는 난이도 규칙이 없어서 켜면 시작 장착만 줄어든 채
적은 그대로인 판이 됩니다. 그건 하드를 잰 것이 아니라 "장착 칸만 다른 일반 판"을 잰 것입니다.
**하드 표가 붙으면 그때 켜십시오.**

### 열여섯 번째 조정 (2026-09-03, 검증 구멍 메우기)

밸런스와 무관하게 **점검이 못 잡고 있던 자리** 넷을 고쳤습니다.

#### (1) 부팅 점검이 게임오버에 확실히 닿게

`npm run check` 의 부팅 점검 6번(게임오버)이 **판마다 되다 말다 했습니다.** 게임 자체는
멀쩡했고 점검 방식이 문제였습니다.

예전 방식은 P키로 200마리를 20묶음마다 붓고 플레이어가 죽기를 기다리는 것이었습니다.
**그런데 그 처치로 들어오는 경험치가 플레이어를 같이 키웁니다.** 같은 스크립트를 반복
실행한 계측입니다.

| 판 | 결과 | 도달 레벨 | 처치 | 버틴 시간 |
|---|---|---|---|---|
| A | 사망 | Lv.34 | 4,000 | 42.9초 |
| B | 사망 | Lv.29 | 2,562 | 34.6초 |
| C | **생존** | Lv.45 | 8,286 | 70초(예산 소진) |

**압박을 키우려고 더 부으면 오히려 반대로 갑니다.** 열 번째 조정(스킬 10레벨 · 곡선 펴기)
뒤로 C 쪽이 자주 나오면서 연달아 실패하고 있었습니다.

**고친 것은 둘입니다.**

- **디버그 즉사 키 X 를 만들었습니다** (`game/debug.ts`). 가장 가까운 적을 사인으로 달아
  `damagePlayer` 로 죽이므로 **사망 원인 표시까지 같이 검증**됩니다. **부활은 그대로
  태웁니다.** 남아 있으면 한 번 되살아나므로 판을 끝내려면 남은 횟수만큼 더 눌러야
  합니다. 여기서 부활을 지우면 그 경로를 영영 못 밟습니다. 무적(G)을 켜둔 채 누르면
  죽은 뒤에 체력만 되돌아오므로 **누르는 순간 무적을 끕니다**
- **부팅 점검 6번이 그 키를 씁니다** (`scripts/boot.ts`). 적을 한 번만 부르는 것은 사망
  원인 칸을 띄우기 위해서이고, 그다음은 X 로 곧장 끝냅니다. 5회 연속 통과를 확인했습니다

**반드시 지킬 것입니다.**

- **싸움의 승패에 점검을 매달지 마십시오.** 밸런스를 만질 때마다 점검이 뒤집히면, 그때마다
  통과할 때까지 조건을 손보게 됩니다. 그건 점검이 아닙니다
- **판이 아직 재현되지 않습니다.** `?seed` 가 없으면 `Rng` 가 `Math.random()` 으로 씨앗을
  뽑는데(`core/rng.ts`), `boot.ts` 는 그것을 안 넘깁니다. 6번은 이제 싸움과 무관하지만
  다른 항목이 흔들리면 여기부터 보십시오

#### (2) 저장에 없는 스킬 id 가 있으면 게임이 안 켜지던 것

`save.ts` 가 시작 스킬 목록을 **배열인지만 보고 통과**시키고 있었습니다. 바로 옆의
`equippedPassives` 는 해금 목록과 대조하는데 이 셋만 그냥 지나갔습니다.

없는 id 를 하나 넣고 돌려보니 이렇습니다.

```
상점에서 터짐 → Cannot read properties of undefined (reading 'kind')
판 시작에서 터짐 → Cannot read properties of undefined (reading 'kind')
```

`getSkillDef` 는 표에 없는 id 에 `undefined` 를 돌려주는데 받는 쪽이 곧바로 `.kind` 를
읽습니다. **터지는 자리가 판 시작(`player.ts`)과 상점(`shop.ts`) 둘 다라, 게임을 켤 수도
없고 고칠 화면에 들어갈 수도 없습니다.** 저장을 통째로 지우는 것 말고 길이 없었습니다.

`knownSkills` 하나로 셋을 다 거릅니다. **`records.bestBuild` 도 같은 목록입니다.**
기록 화면(`menus.ts`)이 그걸로 스킬 이름을 뽑기 때문에 안 거르면 거기서 같이 터집니다.

- **거르는 기준은 `balance.ts` 의 `SKILLS` 입니다.** `save.ts` 가 스킬 등록부를 통째로
  끌어오지 않게 하려는 것이고, 대신 **그 표와 등록부가 같은 목록인지를 `smoke.ts` 16번이
  잽니다.** 두 곳이 갈라지면 거르는 기준 자체가 틀어지므로 이 시험을 지우지 마십시오
- **스킬 id 를 바꾸거나 없앨 때 마이그레이션을 따로 쓸 필요는 없습니다.** 모르는 이름은
  조용히 빠지고 그 자리는 안 산 것이 됩니다. 코인을 돌려주고 싶으면 그때 따로 넣으십시오

#### (3) 투사체 감속이 `slowEnemy` 를 안 거치던 것

`projectile.ts` 가 `e.slow` 를 직접 건드리고 있었습니다. 그 길로는 보스 상태이상
저항(70%)도, 돌진 중 상태이상 면역(`statusImmune`)도 안 걸립니다.

**지금까지 아무 일도 없었던 이유는 `slowFactor` 를 1 미만으로 넣는 스킬이 하나도 없어서**
그 if 문이 한 번도 참이 된 적이 없었기 때문입니다. 감속 투사체를 하나 붙이는 순간 두
규칙이 소리 없이 빠지는 자리였습니다. 지금은 `w.slowEnemy` 를 부릅니다.

#### (4) 검증 스크립트가 타입 검사 밖에 있던 것

`tsconfig.json` 의 `include` 가 `["src"]` 뿐이라 **`npm run check` 의 타입 검사가
`scripts/` 를 아예 안 봤습니다.** 게임의 검증을 그 폴더가 전부 맡고 있는데 정작 그 폴더가
무검사였습니다. `["src", "scripts"]` 로 바꾸자 오류 넷이 나왔습니다.

| 파일 | 무엇이었나 |
|---|---|
| `boot.ts` | `DIFFICULTY.unlockTime` 을 읽는데 **그런 상수가 없습니다.** 다섯 번째 조정에서 해금 규칙이 바뀌며 사라진 값이라, `bestTime` 에 `undefined` 를 넣고 있었습니다 (JSON 이 그 칸을 버려서 겉으로는 멀쩡했습니다). 줄째로 지웠습니다 |
| `boot.ts` | DOM 흉내 객체에 `textContent` 가 빠져 있었습니다 |
| `bot.ts` | 시작 스킬 목록이 `string[]` 로 새고 있었습니다. **`satisfies SkillId[]` 로 바꿨습니다.** `as` 로 덮으면 없는 이름을 적어도 그냥 통과합니다 |
| `smoke.ts` | `generateSkillChoices` 중복 import 와 안 쓰는 `branchMods` |

**앞으로 `scripts/` 도 타입 검사를 받습니다.** 검증 도구를 고칠 때 오류가 나면 그건 도구가
틀린 것이니 무시하지 마십시오.
